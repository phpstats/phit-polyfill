PHP versions

composer.json requires PHP ^8.3, which allows PHP 8.3 and later 8.x releases. CI runs the test suite on PHP 8.3, 8.4, and 8.5. On Linux it runs each version in five modes: without OPcache, with OPcache and no JIT, with the tracing JIT, with opcache.jit=1205, and with opcache.jit=1235. On macOS it runs the OPcache and opcache.jit=1205 modes. No PHP extension is required.

With the extension

  • When the phit extension is loaded, the polyfill’s bootstrap defines nothing, and every Phit\ function is the extension’s. If the loaded extension is older than the phit release the polyfill reproduces, the functions it lacks stay undefined.
  • composer.json declares "provide": {"ext-phit": "*"}. Composer therefore treats a package that requires ext-phit as satisfied by the polyfill. Phit\read_csv and Phit\CsvReader remain unavailable without the extension.

Differences from the extension

  • Phit\read_csv and Phit\CsvReader are not implemented.
  • The listwise-deletion warning is raised with E_USER_WARNING because PHP code cannot raise E_WARNING. The text is identical.
  • Scalar arguments of the wrong type follow PHP’s userland rules: coercion in non-strict files, otherwise TypeError. The extension raises an \Exception.
  • The polyfill’s functions refuse to run under OPcache’s JIT, as described below. The extension runs under any JIT setting.
  • Matrix products above 5×5 follow the extension’s aarch64 build, which uses fused multiply-adds. On an x86-64 CPU without FMA, the extension’s own products can differ from the polyfill’s in the last bit.

Performance

The polyfill runs the extension’s algorithms in PHP. These timings were recorded on 2026-10-28 on an Apple M5 Ultra with PHP 8.5.10, OPcache on, and the JIT off, comparing polyfill commit ab803fd with phit commit 3861d77 in one process. Each design has 10 standard normal predictors plus an intercept.

Model n Polyfill Extension
fit_ols 10,000 26 ms 2.9 ms
fit_ols 100,000 262 ms 29 ms
fit_logistic 10,000 160 ms 7.0 ms
fit_logistic 100,000 1.60 s 72 ms

The mixed models are the slowest part of the polyfill. In the recorded cases it took 13 to 78 times as long as the extension. fit_mixed and fit_lmer repeat a dense QR factorization at every optimizer step, so their cost grows roughly with the cube of the number of random coefficients.

The mixed-model timings were recorded on 2026-10-16 on the same machine and PHP version.

The JIT

The polyfill runs with OPcache and without the JIT. opcache.jit=disable is the default on PHP 8.4 and 8.5. PHP 8.3’s defaults (opcache.jit=tracing with opcache.jit_buffer_size=0) also leave the JIT off. Every Phit\ function the polyfill defines throws an exception with code 1007 while any JIT compiles the process, on every PHP version, before it reads its arguments. The phit extension is not affected and runs under any setting.

The JIT has computed wrong results in the polyfill without an error on all three versions, as described below. These are PHP bugs that can affect any PHP code; the polyfill’s numerical loops trigger them. Refusing every function, rather than the ones that have failed so far, means a miscompile the tests have not found cannot produce a wrong number either.

Phit\Polyfill\Polyfill::implementation() returns an implementation without the check. The test suite uses it, and CI still runs the suite under the tracing JIT, opcache.jit=1205, and opcache.jit=1235 to record the miscompiles.

PHP 8.4 and 8.5

A function JIT with hot-counter triggers compiles a function while it is running and enters the compiled code partway through a loop. In that case PHP can lose the value of a variable that is live across the loop entry (php-src #24214). The polyfill avoids the patterns that triggered the bug in its own code, and its full suite passes under opcache.jit=1235 on both versions. Because the bug is in PHP, other code paths may still meet it.

On PHP 8.4.26 on GitHub’s x86-64 runner, the tracing JIT also miscompiles the BOBYQA optimizer behind the mixed models without any message. One reference case ends at a minimum 18% away from the correct one. The failure has not reproduced on other machines with the same PHP build. PHP 8.5 passes under the tracing JIT in CI, which was also true of PHP 8.4 before this runner.

PHP 8.3

PHP 8.3 uses an older JIT backend, and that release line receives security fixes only. With the tracing JIT, one beta-distribution case in the stress suite returns a value that differs from the extension’s in the 12th digit after certain functions have been compiled. With opcache.jit=1215 or 1235, the PHP process crashes in the test suite.

PHP 8.3’s round() first rounds its argument to 15 significant digits, so round(0.49999999999999994) is 1.0 there. The polyfill uses its own exact rounding, which matches Rust and PHP 8.4.

Optimizer folding with NaN

OPcache’s optimizer rewrites !($x > 0) as $x <= 0, which differs when $x is NaN. The polyfill writes such conditions so that NaN takes the same branch as in the extension, with or without OPcache, on all three versions.
