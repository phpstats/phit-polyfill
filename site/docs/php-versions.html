PHP versions and the JIT

The polyfill supports PHP 8.3, 8.4, and 8.5. CI runs the test suite on each version on Linux in five modes: without OPcache, with OPcache and no JIT, with the tracing JIT, with opcache.jit=1205, and with opcache.jit=1235. On macOS it runs the OPcache and opcache.jit=1205 modes. The PHP versions and JIT modes verification lists the result of every combination with the phit extension loaded.

The rule

Run the polyfill with OPcache and without the JIT (opcache.jit=disable, which is also PHP 8.3’s default). Every Phit\ function the polyfill defines throws an exception with code 1007 while any JIT compiles the process, on every PHP version, before it reads its arguments. The phit extension is not affected and runs under any setting.

The JIT has computed wrong results in the polyfill without an error on all three versions, as described below. These are PHP bugs that can affect any PHP code; the polyfill’s numerical loops trigger them. Refusing every function, rather than the ones that have failed so far, means a miscompile the tests have not found cannot produce a wrong number either.

Phit\Polyfill\Polyfill::implementation() returns an implementation without the check. The test suite uses it, and CI still runs the suite under the tracing JIT, opcache.jit=1205, and opcache.jit=1235 to record the miscompiles.

PHP 8.4 and 8.5

A function JIT with hot-counter triggers compiles a function while it is running and enters the compiled code partway through a loop. In that case PHP can lose the value of a variable that is live across the loop entry (php-src #24214). The polyfill avoids the patterns that triggered the bug in its own code, and its full suite passes under opcache.jit=1235 on both versions. Because the bug is in PHP, other code paths may still meet it.

On PHP 8.4.26 on GitHub’s x86-64 runner, the tracing JIT also miscompiles the BOBYQA optimizer behind the mixed models without any message. One reference case ends at a minimum 18% away from the correct one. The failure has not reproduced on other machines with the same PHP build. PHP 8.5 passes under the tracing JIT in CI, which was also true of PHP 8.4 before this runner.

PHP 8.3

PHP 8.3 uses an older JIT backend, and that release line receives security fixes only. With the tracing JIT, one beta-distribution case in the stress suite returns a value that differs from the extension’s in the 12th digit after certain functions have been compiled. With opcache.jit=1215 or 1235, the PHP process crashes in the test suite.

PHP 8.3’s round() first rounds its argument to 15 significant digits, so round(0.49999999999999994) is 1.0 there. The polyfill uses its own exact rounding, which matches Rust and PHP 8.4.

Optimizer folding with NaN

OPcache’s optimizer rewrites !($x > 0) as $x <= 0, which differs when $x is NaN. The polyfill writes such conditions so that NaN takes the same branch as in the extension, with or without OPcache, on all three versions.
