PHP versions and the JIT

  • Recommended settings
  • PHP 8.4 and 8.5
  • PHP 8.3
  • Optimizer folding with NaN

The polyfill supports PHP 8.3, 8.4, and 8.5. CI runs the test suite on each version on Linux in five modes: without OPcache, with OPcache and no JIT, with the tracing JIT, with opcache.jit=1205, and with opcache.jit=1235. On macOS it runs the OPcache and opcache.jit=1205 modes. The PHP versions and JIT modes verification lists the result of every combination with the phit extension loaded.

Recommended settings

PHP Recommended Avoid
8.3 OPcache without the JIT (PHP 8.3’s default) the tracing JIT; opcache.jit=1215 and 1235
8.4 OPcache without the JIT the tracing JIT; function JIT with hot-counter triggers, such as opcache.jit=1235
8.5 OPcache without the JIT function JIT with hot-counter triggers, such as opcache.jit=1235

The settings to avoid are PHP bugs, and they can affect any PHP code, not only this package. They are recorded here because the polyfill’s numerical loops trigger them.

Phit\fit_mixed, Phit\fit_lmer, Phit\fit_logistic_mixed, and Phit\fit_glmer throw an exception with code 1007 while any JIT compiles the process, on every PHP version. Their optimizer is the code the JIT has miscompiled most severely. Phit\fit_mixed_intercept uses no optimizer and still runs.

PHP 8.4 and 8.5

A function JIT with hot-counter triggers compiles a function while it is running and enters the compiled code partway through a loop. In that case PHP can lose the value of a variable that is live across the loop entry (php-src #24214). The polyfill avoids the patterns that triggered the bug in its own code, and its full suite passes under opcache.jit=1235 on both versions. Because the bug is in PHP, other code paths may still meet it.

On PHP 8.4.26 on GitHub’s x86-64 runner, the tracing JIT also miscompiles the BOBYQA optimizer behind the mixed models without any message. One reference case ends at a minimum 18% away from the correct one. The failure has not reproduced on other machines with the same PHP build. PHP 8.5 passes under the tracing JIT in CI, which was also true of PHP 8.4 before this runner, so OPcache without the JIT is the only setting recommended on either version.

PHP 8.3

PHP 8.3 uses an older JIT backend, and that release line receives security fixes only. With the tracing JIT, one beta-distribution case in the stress suite returns a value that differs from the extension’s in the 12th digit after certain functions have been compiled. With opcache.jit=1215 or 1235, the PHP process crashes in the test suite. OPcache without the JIT and opcache.jit=function (1205) pass every test, and PHP 8.3 disables the JIT by default.

PHP 8.3’s round() first rounds its argument to 15 significant digits, so round(0.49999999999999994) is 1.0 there. The polyfill uses its own exact rounding, which matches Rust and PHP 8.4.

Optimizer folding with NaN

OPcache’s optimizer rewrites !($x > 0) as $x <= 0, which differs when $x is NaN. The polyfill writes such conditions so that NaN takes the same branch as in the extension, with or without OPcache, on all three versions.
