phit-polyfill is a pure-PHP implementation of the phit extension’s functions. When the extension is not loaded, it defines them in the Phit namespace with the extension’s names, parameter names, defaults, result keys, warnings, and exception codes. Code written against phit runs on hosts where the extension cannot be installed, such as shared hosting or a managed platform without custom extensions. When the extension is loaded, the polyfill defines nothing.

The implementations are ports of phit’s Rust code. On every input in the test suites, the polyfill returns the same bits as the extension. It is slower: the recorded regression fits take 9 to 23 times as long, and mixed models 13 to 78 times as long (see Compatibility and limitations).

Installation

composer require phpstats/phit-polyfill

The polyfill supports PHP 8.3, 8.4, and 8.5 (composer.json requires >=8.3 <8.6). CI tests all three. No PHP extension is required.

Composer’s autoloader loads the polyfill’s bootstrap.php. If any version of the phit extension is loaded, the bootstrap defines nothing. Otherwise it declares each function the polyfill implements, unless a function of that name already exists.

The polyfill’s functions throw an exception with code 1007 while OPcache’s JIT compiles the process. Set opcache.jit=disable where the polyfill runs.

Usage

Import functions with use function, or call them by their qualified names.

use function Phit\fit_ols;

$fit = fit_ols(
    x: [[1.2, 0.4], [2.3, 1.1], [3.1, 0.9], [4.8, 2.2], [5.0, 1.7]],
    y: [2.1, 4.2, 5.8, 8.1, 10.2],
);

$fit['coefficients'];
$fit['p_values'];

$fit['coefficients'] is [-0.2843, 2.5864, -1.6819] (rounded here), with the intercept first. The same code runs with the extension loaded.

Checking what is available

Phit\Polyfill\Polyfill reports which functions the polyfill implements and whether the extension is loaded.

use Phit\Polyfill\Polyfill;

Polyfill::supports('Phit\fit_logistic');  // true
Polyfill::supports('Phit\read_csv');      // false: needs the extension
Polyfill::nativeLoaded();                 // whether phit is loaded

Polyfill::implementation('Phit\fit_ols') returns the polyfill’s callable even when the extension is loaded, and it skips the JIT check. The parity tests and the benchmarks use it to run both implementations in one process.
