# phit-polyfill 0.6.1 clean-room mirror: handoff (2026-11-02)

Branch `wip/0.6.1-cleanroom`. The goal is polyfill 0.6.1, which mirrors phit
v0.6.1 (tag on `1eee44a`). phit 0.6.1 replaced its R-derived routines with
clean-room implementations written from `specs/cleanroom/`. The polyfill must
return byte-identical output to the extension. The release is approved by
the coordinator.

## Outcome: released as 0.6.2 (2026-11-02)

There is no polyfill 0.6.1 and no `v0.6.1` tag. The full checks found that
phit 0.6.1 hangs in `saddle.rs` `deviance_term` when `x + np` overflows (see
"Status at 7d41302" below). The coordinator decided to fix phit first and
release both as 0.6.2.

- phit `d8caf83`, tag `v0.6.2`: `deviance_term` evaluates at a quarter of the
  scale above `f64::MAX / 4` and when `x ln(x/np)` alone overflows (D is
  homogeneous of degree one, so this is exact), and the series stops on a
  non-finite sum. `specs/cleanroom/special.md` now defines that regime. Rust
  tests check the values against mpmath, the power-of-two scaling bit for
  bit, and `Beta(12.2, 1e308)`. `scripts/check`, CI on main and on the tag,
  and the release workflow passed; Packagist lists v0.6.2.
- Polyfill: `Saddle.php` mirrors the fix, the fixtures are pinned to
  `d8caf83`, and the docs name 0.6.2. `optimizeFunctions()` moved to
  `tests/Support/optimize.php`, so `OptimizeParityTest` runs on its own.
- Checks against the dylib built from tag `v0.6.2`: without the extension
  on PHP 8.5 and 8.4, 715 passed and 134 skipped; tracing JIT, 601 passed and
  248 skipped by design; the suite with the extension minus the extreme
  grid, 827 passed and 14 skipped by design; `DistributionsExtremeParityTest`,
  all 7 families (14,695 comparisons); randomized parity at 1000 iterations
  on seeds 1, 42, 20261102 and 987654321; Optimize, Smoothing and Descriptive
  parity on the same seeds; lint.

### Open: the extreme grid is slow in the polyfill

`DistributionsExtremeParityTest` takes about 68 minutes serially (nbinom_mu
26 min, beta 22, F 15, gamma 6). About 1,300 of its calls end in 1006 after a
continued fraction or series runs to `MAX_ITER = 1_000_000`, which phit uses
too: milliseconds in Rust, about 0.25 s in PHP, and repeated inside quantile
root searches. The results match; only the time differs. Lowering the cap
would have to start in phit to keep parity. Run the families in parallel with
`--filter 'dataset "beta"'` and so on.

## Status at 7d41302 and 05301b3 (second session)

- Items 1, 2, 3, 5 and 6 are done and pushed. The extension was rebuilt at
  `1eee44a` (the earlier dylib was stale).
- Spec tables: optimize, uniroot, approx, quantile7, format, round, format_g,
  format_pval and coefmat match R exactly. dnorm is within 3.9e-16 where the
  result is normal, and one smallest subnormal low at z = -38.2, which the
  spec allows. The polyfill matches the extension there bit for bit.
- Passing: no-extension suites on PHP 8.5 and 8.4 (712 passed, 134 skipped),
  tracing JIT (598 passed, 248 skipped by design), lint, Optimize, Smoothing
  and Descriptive parity on seeds 1, 42, 20261102 and 987654321 at 1000
  iterations, and randomized parity on seed 20261102.
- **Blocked: phit 0.6.1 hangs, and the polyfill mirrors the hang.**
  `saddle.rs` `deviance_term(x, np)` loops forever when `2x` overflows:
  for x ≈ 1e308 and np ≈ 9.9e307, `x + np` is INF, so `v = 0` and
  `pow = 2x·v = INF·0 = NaN`, and `next == sum` never holds for NaN. It is
  reached through the beta distribution's saddle-point binomial term, so
  `Phit\dist_beta_logpdf(0.01, 12.2, 1e308)` and the beta cdf, sf, quantile
  and rng hang in the extension. `DistributionsExtremeParityTest` (a and b up
  to PHP_FLOAT_MAX) therefore never finishes, nor does randomized parity on
  seeds 1, 42 and 987654321 (seed 1 stops at round 745,
  `dist_beta_rng(1, 9107391473943085827, 12.205917989158033, 1e308)`).
  The fix belongs in phit, followed by the same change in `Saddle.php`. Not
  tagged; waiting on that decision.
